SYNC — CHECKOUT DIRECTORY LINKS

At the Git working-tree root, including in a linked worktree:

  seihou sync
  seihou sync --dry-run
  seihou sync --json

Sync reads checkout declarations from .seihou/manifest.json, creates missing
links, repairs wrong symlink targets, and leaves correct relative links alone.
No installed producers, network, config evaluation, migrations or shell commands
are needed. It never changes the manifest or upgrades an artifact. Rerun it to
restore deleted links. Human output lists links and summarizes the result.

DECLARING LINKS

  With S bound to the schema import generated by `seihou new-module`:

    S.Step::{ strategy = "symlink", src = "agents/skills/my-skill",
              dest = ".agents/skills/my-skill", lifecycle = Some "checkout" }

  src names a real directory in the consuming project, not module files/.
  Ignore the discovery destination, apply the declaring module, then commit
  the manifest, source directory and ignore rule. Another clone needs only sync.
  Paths must be safe project-relative paths with no overlapping sources or
  destinations; .git and .seihou components are reserved. Patches are forbidden.

ADOPTING EXISTING APPLICATIONS

  seihou update TARGET

  Use the recorded root target (shown by status or sync when no declarations
  exist). Update fetches its source/dependencies and reuses recorded inputs;
  installing modules or upgrading the manifest alone cannot infer link intent
  from old command receipts. No prerequisite installation list is required.

  If an ignored destination is an unchanged tracked symlink matching the
  declaration, the update preview proposes `Adopt link:`. Accepting removes
  that entry from Git's index while keeping its working link. Commit the
  accepted removal with the updated manifest, sources and ignore rules.
  Modified/staged links and regular objects remain protected. Dry-run and
  cancellation leave the index untouched; failed/interrupted uncommitted
  updates recover adopted entries without replacing unrelated staging.

REFUSALS AND RECOVERY

  Sync protects tracked paths even if absent on disk. It refuses real files
  and directories at destinations, symlinked ancestors, missing sources,
  unsafe metadata and ambiguous native paths. Move a collision aside or fix
  the source/declaration explicitly; there is no force flag. Run at the Git
  root named by the error; nested Seihou projects are not supported yet.

  All declarations are checked before writing, so a refused preflight writes
  nothing. An ordinary apply failure rolls back this attempt where safe. A
  killed process may leave correct partial links; rerun sync to converge.
  Empty and already-correct plans succeed. Older supported manifests with no
  declarations report no work and suggest recorded update targets.
