# Improvement Request

- [Add a not-applicable outcome for blueprint migration edges](add-a-not-applicable-outcome-for-blueprint-migration-edges.md) - Give a blueprint migration edge a way to report that its precondition is unmet so the edge is left unrecorded, instead of a deliberate no-op returning a receipt indistinguishable from a completed upgrade.
- [Declare and install cross-registry recipe dependencies](declare-and-install-cross-registry-recipe-dependencies.md) - Let a recipe declare authoritative sources for modules in other registries and install the required dependency closure through the ordinary install command without requiring users to install whole registries or guess module origins.
- [Exempt additive-patch paths from the shared-ownership closure, and offer an opt-in to expand it](exempt-additive-patch-paths-from-shared-ownership-closure.md) - Stop a targeted `seihou update` from failing on a shared path that every owner writes with an additive, idempotent patch (append-line-if-absent, append-section), where reconciling one owner provably cannot corrupt another's contribution; and add an explicit opt-in flag that expands a named selection to the full ownership closure for the paths where the requirement still holds.
- [Extend an existing recipe with a single base](extend-an-existing-recipe-with-a-single-base.md) - Let a recipe reuse one existing recipe and add modules or override bindings, with dependency installation, deterministic expansion, validation, and provenance handled by Seihou instead of copied module lists or Dhall imports.
- [Fail a batch blueprint run whose agent was refused tools](fail-a-batch-blueprint-run-whose-agent-was-refused-tools.md) - Make seihou agent run --batch exit non-zero, and name the refused commands, when the agent was denied tools during the run, instead of exiting 0 after an hour of work the blueprint could not do; and warn at validation when a blueprint declares no allowedTools.
- [Fail a non-interactive update that applied nothing](fail-a-non-interactive-update-that-applied-nothing.md) - Stop plain seihou update from reporting success when it has no terminal to confirm on, since it currently changes nothing, ignores piped answers, shows no prompt, exits 0 and gives no hint that --json is the non-interactive path.
- [Guard the agent path against stale and substituted artifacts](guard-the-agent-path-against-stale-and-substituted-artifacts.md) - Apply the ADR 0003 refusal to seihou agent run and seihou agent migrate, which write baseline files and migration receipts today without ever consulting ManifestGuard, so a substituted or downgraded blueprint is caught on the agent path as it already is on the module path.
- [Keep an auditable tool-call record of a batch blueprint run](keep-an-auditable-tool-call-record-of-a-batch-blueprint-run.md) - Give a batch seihou agent run on claude-cli a way to keep the agent's tool calls, because Baikai launches Claude with --no-session-persistence and the trace sink records only call timing, so nobody can show afterwards which commands an unattended agent executed.
- [Keep saved inputs when a release changes a dependency's bindings](keep-saved-inputs-when-a-release-changes-dependency-bindings.md) - Stop seihou update from treating an instance as new when a module release adds a binding to a dependency edge, which today either fails on required variables the project already saved or, once those are supplied, silently resets the project's optional inputs to their defaults.
- [Rebuild checkout-local outputs, such as skill symlinks, in a fresh clone](rebuild-checkout-local-outputs-in-a-fresh-clone.md) - Let a module declare outputs that exist only in a working copy, such as gitignored symlinks, and give a fresh clone one command that rebuilds them from the manifest without upgrading any artifact. Today the committed command receipts tell every clone that the work is done, so a cloner cannot get `link-skill`'s symlinks back without an unrelated upgrade.
- [Record artifact origin for agent-applied artifacts](record-artifact-origin-for-agent-applied-artifacts.md) - Give AppliedBlueprint, AppliedBlueprintMigration, and AppliedRecipe the same ArtifactOrigin the module records already carry, so manifest provenance for agent-run artifacts is an identity ADR 0002 accepts rather than the bare name it explicitly rejects.
- [Record command receipts in a manifest that a module command can commit](record-command-receipts-before-commands-can-commit-them.md) - Stop seihou from writing command receipts only after every module command has finished, which leaves .seihou/manifest.json modified immediately after any module whose own commands commit or push the project (git-init), and makes the committed and pushed manifest claim that no command has ever run.
- [Refresh installed blueprints in seihou upgrade](refresh-installed-blueprints-in-seihou-upgrade.md) - Make seihou upgrade refresh installed blueprints from their source repositories, as it already does for modules and recipes, so that publishing a blueprint fix and running seihou upgrade puts the fix in front of the next seihou agent run.
- [Refuse to overwrite an installation from a different source](refuse-to-overwrite-an-installation-from-a-different-source.md) - Make seihou install read the origin metadata it is about to delete and refuse when the incoming artifact comes from a different repository, instead of warning and replacing, since the install cache is keyed by bare name and a registry entry has no rename escape hatch.
- [Resolve recipe variables and prompts before module resolution](resolve-recipe-variables-and-prompts-before-module-resolution.md) - Honor recipe-level declarations and prompts so a recipe can ask once for an optional feature and pass the answer to every composed module instead of silently using module defaults.
- [Supply an initial instruction to CLI providers, or require one](supply-an-initial-instruction-to-cli-providers.md) - Make seihou agent migrate work without a trailing PROMPT on the default claude-cli provider, which today fails on its first edge because claude -p requires a user message and seihou sends only a system prompt.
- [Tell off-plan refusals from missing tools in a batch blueprint run](tell-off-plan-refusals-from-missing-tools-in-batch-runs.md) - Let a batch blueprint run that finished its work despite refused calls the blueprint never asked for (wrapped commands, filesystem-wide searches, calls added by the user's own hooks) be reported as completed with refusals instead of failing outright, so the refusal check from IR-18 stops discarding finished, valid runs.
- [Truncate the blueprint prompt in status output](truncate-the-blueprint-prompt-in-status-output.md) - Stop seihou status from echoing the entire stored blueprint prompt verbatim, which for a detailed positional prompt floods the scannable summary with a wall of text; truncate it the way blueprint migration reasons are already truncated, and keep the whole of it in the manifest.
- [Let seihou update reconcile module files that seihou run wrote under .seihou](update-module-files-that-seihou-run-wrote-under-dot-seihou.md) - Resolve the disagreement between seihou run, which lets a module generate files under .seihou/, and seihou update, which refuses to reconcile any managed path there, so that applications of recipes such as fumadocs-site can be updated instead of forcibly reapplied.
- [Validate a recipe without running its composition](validate-a-recipe-without-running-its-composition.md) - Provide a discoverable recipe validation command that checks recipe declarations and prompts without generating files, executing module commands, or requiring answers to project configuration questions.
- [Verify an entailed edge is reachable by consumers, not just declared locally](verify-an-entailed-edge-is-reachable-by-consumers.md) - Give a blueprint author a way to check that an entailed blueprint's exact edge resolves from the source consumers install from, since validate-blueprint correctly ignores the question and the --debug preview answers it against the author's own working tree.
